FAQ & data notes

How to read this page and what the underlying data can — and cannot — prove.
{% if faq_path == '/home' %}
What is EVEOSINT?
EVEOSINT is an analytical interface built from public EVE Online data sources. It combines static game data, public entity information, killmail history and Monthly Economic Report data to make historical and behavioural analysis easier.
Is EVEOSINT a live view of the game?
No. Data is imported and processed in scheduled batches. During an update, the banner at the top of the site warns that some results may temporarily be behind the newest available source data.
Does a missing result mean that something never existed?
No. EVEOSINT can only analyse evidence present in its source datasets. Missing public evidence must not be interpreted as proof that an activity, character, ship or relationship never existed.
{% elif faq_path == '/profiles' %}
What can I search here?
The Profiles page searches known characters, corporations and alliances and opens their EVEOSINT profile pages.
Why can a valid EVE entity be missing?
The search operates on entities known to the local EVEOSINT dataset. An entity can be absent or temporarily outdated if it has not yet been discovered, imported or refreshed from the available public sources.
{% elif faq_path == '/killboard' %}
What does the global Killboard show?
It searches the normalized killmail history stored by EVEOSINT. With no active filter it shows recent killmails; historical filtered searches scan the available history progressively instead of running one very large query.
How do the + and − filters work?
A + term includes matching ships, locations or entities. A − term excludes them. If a filter family has no + term, that family starts from ALL and only the − terms are removed.
What locations can be filtered?
You can search systems, constellations and regions, or use the Highsec, Lowsec, Nullsec, Pochven and Wormhole presets.
Why can a filtered search take longer?
Large historical searches are processed month by month and stop once enough matching results have been found. This avoids forcing the database to scan the entire history in one request.
{% elif faq_path.startswith('/kill/mer/') %}
What is this MER kill record?
This page comes from CCP Monthly Economic Report kill data rather than a normal uniquely identified API killmail.
What does “hidden” mean?
A hidden MER record is a MER kill for which EVEOSINT currently has no matched normalized killmail. It is evidence from the MER dataset, but it does not provide the same detail as an API killmail.
What does “ambiguous” mean?
The MER row matched more than one possible normalized killmail, so EVEOSINT does not silently choose one. Candidate killmails are shown when available.
{% elif faq_path.startswith('/kill/') %}
Where does this killmail come from?
The detailed killmail page is built from EVEOSINT's normalized killmail dataset and enriched with locally imported EVE static data and known entity information.
What does “Copy EFT” do?
It converts the available victim fitting and cargo information into an EFT-style text representation. The result can only include items present in the source killmail.
Why can some attacker or fitting information be missing?
EVEOSINT displays the evidence contained in the source killmail. If a source field is absent, there may be nothing reliable to display or infer.
{% elif faq_path == '/map' or faq_path.startswith('/map/') %}
What does the map represent?
The map is built from imported EVE Static Data Export topology and celestial data. It provides navigation and geographic context for New Eden rather than live player positions.
What do HS, LS and 0.0 mean?
They filter the displayed systems by high-security, low-security and null-security space. Pochven and wormhole-space data are handled separately where relevant in search and killboard filters.
Can I open the kill history of a location?
Yes. Region, constellation and system profiles link the map and the killboard so the same location can be explored geographically and historically.
{% elif faq_path == '/ship-analysis' %}
What does Ship Analysis measure?
It builds time series from killmail evidence. A series can measure unique observed pilots or uses, optionally as a percentage, and can be restricted by ship, side of the killmail, alliance, corporation and location.
What is the activity window?
For unique-pilot metrics, the activity window controls how long an observed pilot remains active in the series after an event. “Infinite” keeps the pilot active for the rest of the selected graph period.
Can several populations be compared?
Yes. The page supports multiple independent series, each with its own filters and metric, so different ships, groups or areas can be compared over the same period.
Why can a long analysis take time?
Historical analysis may scan many monthly killmail partitions. EVEOSINT uses bounded queries and progressive processing to reduce the risk of one large request blocking the application.
{% elif faq_path.startswith('/corporation/') and '/pilotable-ships/' in faq_path or faq_path.startswith('/alliance/') and '/pilotable-ships/' in faq_path %}
What does “pilotable” mean here?
It is an inference from public killmail evidence, not the character's private ESI skill sheet. EVEOSINT infers minimum observed skills from ships, weapons and fitted items and checks which ships those inferred skills satisfy.
Does this prove that every listed pilot can currently fly the ship?
No. It shows that the available evidence supports the required minimum skill set. Public evidence can be incomplete, historical or absent.
Can a capable pilot be missing?
Yes. If the killmail history never exposes enough relevant evidence for that character, EVEOSINT cannot safely infer skills it has not observed.
{% elif faq_path == '/ship-category' or faq_path.startswith('/ship/') %}
What is shown on a ship page?
Ship pages combine Static Data Export information with EVEOSINT analysis tools such as ranking, killboard filtering and historical activity analysis.
Where do ship attributes and bonuses come from?
Static ship metadata, groups, traits and dogma attributes come from the locally imported EVE Static Data Export.
Are rankings an official EVE statistic?
No. They are EVEOSINT calculations over the data available in this installation and should be interpreted as analytical output, not an official CCP leaderboard.
{% elif faq_path.startswith('/weapon/') or faq_path.startswith('/skill/') or faq_path.startswith('/commodity/') %}
Where does this item information come from?
The profile is based primarily on the locally imported EVE Static Data Export. Where EVEOSINT has relevant killmail evidence, the item can also be linked into analysis and killmail views.
Why are some SDE fields empty?
Not every EVE type exposes the same attributes, traits or relationships. EVEOSINT does not invent values when a field is not present in the imported static data.
{% elif faq_path.startswith('/character/') or faq_path.startswith('/corporation/') or faq_path.startswith('/alliance/') or faq_path.startswith('/system/') or faq_path.startswith('/constellation/') or faq_path.startswith('/region/') %}
What is an entity profile?
It is EVEOSINT's consolidated view of one known character, corporation, alliance or location, with links to the related public history and killmail evidence available locally.
Are affiliations guaranteed to be current?
No. Character and corporation affiliations are refreshed from public ESI information and historical records, but there can be a delay between an in-game change, its source availability and the next EVEOSINT refresh.
What are “API”, “TOTAL” and “Only hidden” on entity killboards?
API uses normalized public killmails. TOTAL uses the broader MER kill dataset where supported. Only hidden shows MER records that are not currently matched to a normalized killmail.
Why do MER and API views not support exactly the same filters?
The MER dataset does not contain every field available in a detailed killmail. EVEOSINT only applies filters that can be supported by the selected source rather than fabricating missing detail.
{% elif faq_path.startswith('/entities/') %}
What is EntitiesINTEL?
EntitiesINTEL is the catalogue and profile layer for characters, corporations, alliances, ships, skills, commodities and EVE geography known to EVEOSINT.
Why do some pages show recently involved entities while others show a catalogue?
Character, corporation and alliance pages are oriented toward entities observed in activity, while static game objects such as ships, skills and commodities are primarily sourced from the imported SDE catalogue.
Can I search across modules?
Yes. The global search in the top bar can open supported entity and location pages directly.
{% elif faq_path == '/superintel' %}
What is SuperINTEL?
SuperINTEL reconstructs observable Titan and Supercarrier ownership signals from public killmail evidence. It builds ship sessions per pilot and aggregates the ships considered alive at each report date.
How is the score calculated?
The current score is 3 points per Titan + 1 point per Supercarrier. Rankings can be viewed by alliance, corporation or player.
Does SuperINTEL show exact in-game assets?
No. It is an OSINT inference from observable public evidence. A ship that has never appeared in the available evidence cannot be discovered, and historical evidence can produce uncertainty until later events clarify it.
What are the 7-day and monthly gains/losses?
They compare daily SuperINTEL snapshots and show changes in the inferred Titan/Supercarrier stock and score between the selected dates.
{% elif faq_path == '/superintel/detailed' %}
What does the Detailed dashboard add?
It breaks the inferred stock down hull by hull and adds movement analysis over 7-day or 1-month windows.
What do the movement statuses mean?
ALLIANCE ENTRANCE, ALLIANCE LEAVE and NEW SUPER PILOT describe affiliation or population movement between the compared snapshots. NO CHANGE means no classified movement was found.
What do CREATED, KILLED, UNKNOWN and DELETED mean?
They are EVEOSINT explanations for an observed hull-count change. CREATED and KILLED require supporting public event evidence; UNKNOWN is used when the change cannot be confidently explained from available evidence, and DELETED covers a disappearance classified as deletion rather than a confirmed kill.
Why can an explanation remain UNKNOWN?
EVEOSINT deliberately avoids turning an unsupported correlation into a fact. If the public evidence cannot explain a change reliably, the result remains uncertain.
{% elif faq_path == '/superintel/evolution' %}
What does the Evolution page graph?
It graphs SuperINTEL daily snapshots over time for selected Titan/Supercarrier hulls and selected populations.
What are UNIVERSE and NO_ALLIANCE?
UNIVERSE represents the complete observable SuperINTEL population for the selected hulls. NO_ALLIANCE isolates pilots that are not associated with an alliance in the corresponding snapshot.
What do + and − terms do in a group?
They build arithmetic groups. For example, a series can start with UNIVERSE and subtract one or more alliances to show the remainder of the observable population.
Can the graph data be exported?
Yes. The same generated series can be viewed as a CSV table and downloaded as CSV.
{% elif faq_path == '/superintel/monthly-analysis' %}
What does Monthly Analysis compare?
It compares a selected SuperINTEL daily snapshot with the corresponding day of the previous month and reports the resulting changes by pilot, corporation, alliance or explanation view.
Can the analysis be filtered and sorted?
Yes. The table supports search, per-column filters, sorting, pagination and reason filters where the Explain view is used.
Can I export the result?
Yes. The selected monthly period can be downloaded as an Excel workbook.

Where does EVEOSINT data come from?
EVEOSINT combines locally imported public EVE data such as the Static Data Export, public ESI information, killmail history and Monthly Economic Report datasets.
Can every displayed value be treated as an in-game fact?
No. Some pages display direct source fields while others display calculations or OSINT inferences. Where evidence is incomplete, EVEOSINT is designed to preserve that uncertainty rather than invent a value.
